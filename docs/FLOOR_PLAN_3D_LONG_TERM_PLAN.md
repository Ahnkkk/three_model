# 도면 → 3D 변환 애플리케이션 장기 개발 계획

- 작성일: 2026-11-24
- 상태: 후속 개발 제안·미구현
- 선행 조건: [단기 계획](./FLOOR_PLAN_3D_SHORT_TERM_PLAN.md)의 입력 규격·변환·AI 초안·보정·평가 흐름이 동작할 것
- 목표: 도면 형식과 공간 구조를 확대하고, 인식 결과를 검증·수정·저장할 수 있는 지속적인 업무 도구로 발전시킨다.
- 일정: 기능 목록은 우선순위와 의존 관계를 나타낸다. 일정·인력·비용은 단기 평가 결과를 보고 산정한다.

## 1. 장기에도 유지할 원칙

1. 외부 도면은 공통 도면 문서로 정규화하고, 렌더러는 검증된 문서를 사용한다.
2. 원본에서 확인한 값, 계산값, 기본값, 사용자 수정값을 추적한다.
3. 도면에 없는 높이·형상·가구 디테일을 확정 사실처럼 생성하지 않는다.
4. 2D·3D·충돌·내보내기가 같은 공간 데이터를 사용한다.
5. 자동화 수준을 높여도 사용자의 수정과 수동 경로를 유지한다.
6. 기존 문서 버전의 읽기·마이그레이션과 저장본의 재현성을 유지한다.

## 2. 우선순위와 착수 조건

| 단계 | 우선순위 | 착수 조건 | 주요 결과 |
| --- | --- | --- | --- |
| L1. 인식 품질 고도화 | 높음 | 단기 평가와 수정 이력 확보 | 벽·개구부·치수 연결 개선 |
| L2. PDF·CAD 입력 | 높음 | 공통 문서와 입력 어댑터 안정화 | 실제 업무 도면 형식 확대 |
| L3. 비정형 공간·다층 | 중간 | 새 형상 규격과 기하 검증 설계 | 직사각형 단층 제한 해소 |
| L4. 가구·재질 편집 | 중간 | 편집 상태·실행 취소·기본 카탈로그 안정화, 단기 S3의 리소스 갱신 분리 | 상세 배치와 표현 확대 |
| L5. 프로젝트 저장·공유·운영 | 사용 수요에 따라 조정 | 보존 정책·배포 환경·사용자 구분 결정 | 재개·공유 가능한 업무 흐름 |
| L6. 조명·성능 고도화 | 측정 기반 | 대상 장면·기기·품질 예산 확보 | 큰 공간의 안정성과 표현 개선 |
| L7. 제한된 AI Agent | 조건부 | 반복 도구 실행의 효과가 단순 호출보다 큼을 입증 | 분석·검증 반복의 선택적 자동화 |

L2의 제한된 직사각형 도면 입력은 L3 전체를 기다릴 필요가 없다. L5는 저장·공유 수요가 먼저 생기면 앞당길 수 있다. L7은 다른 장기 기능의 필수 선행 조건이 아니다.

## 3. L1 — 도면 인식 품질 고도화

### 작업

- 도면을 치수·벽·문·창·가구·주석 등으로 분리하고, 요소 사이의 관계를 함께 추출한다.
- 치수선·보조선의 연결과 길이 합계, 평행·직교·접합 관계를 이용해 결과를 검산한다.
- 겹친 선, 이중 벽선, 끊긴 선, 얇은 유리선, 가구 기호의 변형을 유형별로 처리한다.
- 모델이 잘 읽는 유형과 실패하는 유형을 구분하고, 사용자 수정량이 큰 유형부터 개선한다.
- 선택 영역만 다시 분석하는 기능을 추가하고, 이미 확인된 데이터와 재분석 초안의 차이를 검토하게 한다.
- 촬영본의 원근·회전 보정을 추가할 경우 보정 전후 좌표 변환과 오차를 보존한다.
- 충분한 실제 평가 자료가 확보된 후에만 규칙 기반 처리, 별도 인식 모델, 모델 학습·튜닝의 필요성을 결정한다.

### 완료 기준

고정 평가 세트에서 이전 버전 대비 위치 오차·누락·오검출·수정 시간이 어떻게 변했는지 보고할 수 있다. 모델이나 프롬프트 변경이 기존 성공 사례를 악화시키는지도 확인한다. 신뢰도 점수 하나로 정확성을 판정하지 않는다.

## 4. L2 — PDF·CAD 입력 확대

| 입력 | 처리 방향 | 주의할 점 |
| --- | --- | --- |
| 스캔 PDF | 페이지 선택 후 이미지 흐름으로 연결 | 해상도·회전·실제 배율·페이지별 도면 분리 |
| 벡터 PDF | 가능한 선·문자 정보를 추출하고 필요한 부분만 이미지 분석 | 페이지 좌표가 실제 m 좌표와 같다는 가정 금지 |
| DXF | 선·폴리라인·문자·치수·블록과 변환을 공통 문서로 매핑 | 단위 누락, 블록 배율·회전, 레이어별 의미 차이 |
| DWG | 선정한 변환 도구나 서비스로 지원 가능한 중간 형식 생성 | 라이선스·배포 방식·변환 손실·운영 비용 검토 |
| IFC | 공간·벽·개구부·층·배치 정보를 전용 어댑터로 변환 | 이미 3D 정보를 가진 입력과 2D 추론 입력을 구분 |

파일에서 선을 읽는 것과 그 선이 벽인지 판단하는 것은 별개다. 레이어 이름만으로 의미를 확정하지 않고 매핑 설정과 사용자 확인을 제공한다. DXF의 단위가 미지정된 경우 실제 길이 기준으로 보정한다.

### 완료 기준

각 지원 형식에 대해 실제 입력 예제·지원 엔티티·미지원 항목·단위 처리·변환 손실을 기록한다. 같은 공간을 이미지와 CAD로 가져왔을 때 정규화된 치수와 배치가 허용 오차 안에서 일치한다. 새 도구 도입 시 공식 문서와 실제 버전으로 기능·라이선스를 다시 확인한다.

## 5. L3 — 비정형 공간과 다층 지원

### 현재 구조의 전제

현재 외곽 처리는 직사각형 한 개를 전제로 한다. 이 단계는 기존 구조를 확장하는 작업이 아니라 아래 전제를 바꾸는 재설계로 취급한다.

- `RoomConfig`는 폭·깊이 두 값과 4방위 `WallId`(`north`/`east`/`south`/`west`)로 외곽을 표현한다.
- 표면은 바닥·천장·외벽 4면의 고정 6면 프레임이며, 라이트맵 UV는 각 면의 폭·깊이·높이로 정규화한다.
- 외벽 보행 충돌은 벽 충돌체가 아니라 카메라 위치 범위(`positionBounds`) 상자로 막는다. 비정형 외곽에서는 외벽을 실제 충돌체로 만들어야 한다.
- 동선 검증·미니맵·조감도 `fit` 시점은 방 사각형 범위를 기준으로 계산한다.

### 새 규격과 기하 처리

- 외곽을 폭·깊이에서 폐합 폴리곤과 내부 구멍으로 확장하고, 직사각형 v1 문서의 변환 규칙을 제공한다.
- 외벽도 일반 벽 ID로 식별한다. v1의 방위별 ID·방향·개구부 거리를 변환할 수 있게 한다.
- 벽 접합, T자 교차, 코너, 두께 차이, 내부 창문 하단 높이를 지원한다.
- 기둥·보·천장 단차·곡선 벽 등은 실제 도면 수요에 따라 순차 추가한다.
- 층별 기준 높이·천장·슬래브·계단·상하층 연결을 정의한다. 연결 정보가 없는 층을 임의로 이어 붙이지 않는다.
- 다층·비정형 바닥에 맞춰 충돌, 미니맵, 카메라 이동 범위와 시작 위치를 함께 변경한다. 외벽을 일반 벽 충돌체로 바꾸고, 카메라 위치 범위 상자는 보조 제한으로만 쓴다.
- 표면 목록을 가변으로 바꾸고 표면 ID·UV·라이트맵 연결을 L6과 함께 설계한다.

현재 내부 파티션 개구부는 바닥에 닿는 문·통로를 중심으로 구현되어 있다. 내부 창은 데이터에 `bottom`을 추가하는 것뿐 아니라 메시·2D·충돌 처리까지 함께 확장해야 한다.

### 완료 기준

L자 외곽, 내부 구멍이 있는 바닥, 내부 창, 서로 연결된 두 층의 대표 사례를 검증한다. 자기 교차 폴리곤·열린 외곽·중복 벽은 오류로 보고하며 2D·3D·충돌 결과가 일치해야 한다. 이 단계의 형상 확장을 기존 여섯 표면 라이트맵 구조에 억지로 맞추지 않는다.

## 6. L4 — 가구 카탈로그와 편집 확대

- 단기 S3의 리소스 갱신 분리를 전제로 한다. 장면 객체가 바뀔 때마다 재질·라이트맵·환경맵을 다시 만드는 구조에서는 이동·회전·재질 변경을 실시간으로 반영할 수 없다.
- 가구 종류와 구체적인 모델 자산을 분리하고, 크기·축·원점·기본 footprint를 카탈로그에서 관리한다.
- 도면에서 의자 기호를 읽었다는 사실과 실제 제품 모델을 알아냈다는 주장을 구분한다.
- 미분류 가구는 단순 형태로 유지한 뒤 사용자가 종류·모델·치수를 선택하게 한다.
- 가구 이동·회전·교체·복제, 벽·바닥·가구 재질 변경, 스냅과 실행 취소를 제공한다.
- 외부 GLB의 실제 표시 크기와 충돌·2D footprint의 차이를 확인한다. 현재의 균등 fit은 모든 축을 지정 크기와 정확히 일치시키지 않을 수 있다.
- 가구 그룹과 생성된 자식 가구의 관계를 기록해 의자·모니터가 중복 생성되지 않게 한다.
- 가구와 문 열림, 보행 영역의 간섭을 검토한다. 검토 결과를 시공 적합성 보장으로 표현하지 않는다.

완료 기준: 모델을 교체하거나 편집한 뒤 2D·3D·충돌 정보가 함께 갱신되고, 저장·다시 열기 후 같은 배치가 재현된다.

## 7. L5 — 프로젝트 저장·공유·운영

### 저장과 재현

현재 앱에는 저장소·계정이 없고, 단기 범위의 저장은 JSON 내보내기·불러오기다. 서버 API는 S4의 AI 추출 경계(`/api/floor-plan/extract`) 하나뿐이며 인증이 없고, 요청 한도(동시 실행·시간당 요청)는 서버 프로세스 메모리에만 있다. 이 단계에서 계정·권한을 붙이고, 한도와 사용량 기록을 여러 인스턴스가 공유하는 저장소로 옮긴다.

- 원본 도면, 정규화 문서, 사용자 수정, 이슈, 문서 버전, 분석 모델·프롬프트 버전을 연결해 저장한다.
- 프로젝트·도면·revision·분석 작업 ID를 구분하고 새 분석이 기존 확정본을 덮어쓰지 않게 한다.
- 원본을 보관하지 않는 설정에서도 가능한 기능과 재분석 제한을 명시한다.
- 장시간 분석은 진행 상태·취소·재시도·중복 요청 방지를 가진 작업으로 처리한다.
- 필요에 따라 계정·권한·공유 링크·공동 편집을 추가한다. 공동 편집 전 변경 충돌 정책을 정한다.
- JSON 외에 이미지·모델 출력이 필요한지 확인하고, 편집 가능한 원본 문서와 배포용 출력물을 구분한다.

### 운영 조건

- 파일 종류·용량·페이지 수·픽셀 수·도형 수·분석 시간·비용 한도를 정한다.
- 원본의 외부 전송 범위, 저장 위치, 보존 기간, 삭제·다운로드 정책을 문서화한다.
- 사용자별 접근 통제와 API 키 보관을 구현하고 민감한 도면의 원문 로그 노출을 제한한다.
- 모델 공급자 장애, 잘못된 응답, 요청 한도 초과에서도 수동 편집·기존 저장본 열기가 가능하게 한다.

완료 기준: 사용자가 작업을 저장하고 나중에 재개할 수 있으며, 수정 이력과 분석 결과의 출처가 이어진다. 실패·취소된 작업은 정상 완료로 표시되지 않는다.

## 8. L6 — 조명과 성능 고도화

현재 베이커는 외곽 여섯 면의 간접광과 접촉 차폐를 근사한다. 내부 구획의 정확한 광선 차폐와 여러 방 사이의 광 전달을 계산하는 엔진으로 취급하지 않는다.

베이크는 리소스 준비 단계의 메인 스레드에서 동기 실행되며, 표시 모드별로 여러 세트(사무실은 실내 조명 켬·끔과 조감도의 3세트)를 굽는다. 텍셀 수는 표면 면적에 비례하므로 큰 도면에서 준비 시간과 화면 멈춤이 커진다. 단기 S3에서 분리하지 못한 부분이 있으면 이 단계에서 워커 분리를 우선한다.

- 임의 표면 ID·UV·재질·베이크 연결을 도입해 비정형 공간을 지원한다.
- 편집 중 저비용 미리보기와 편집 완료 후 품질 갱신을 분리한다.
- 배치·벽·개구부·재질·광원이 바뀌면 관련 베이크·반사 결과를 갱신한다. 캐시를 도입한다면 문서 revision과 관련 설정으로 무효화한다.
- 실제 필요와 측정 결과에 따라 방별 반사, 실제 베이크, 동적 간접광 방식을 선정한다.
- 반복 가구 인스턴싱·단계별 디테일·점진 로딩·CPU 작업 분리를 검토한다.
- 대상 기기별 준비 시간, 프레임 시간, 드로콜, 메모리와 연속 도면 교체 후 리소스 증가를 측정한다.
- WebGPU·WebGL 2의 지원 품질을 구분하고 모바일은 별도 대상 기기와 조작 기준으로 평가한다.

완료 기준: 정의한 대표 공간과 기기에서 성능 예산을 검증한다. 기존 거실·사무실의 측정값을 임의 외부 도면의 성능 보장으로 사용하지 않는다.

## 9. L7 — 조건부 AI Agent 도입

### 단기 모델 호출과의 차이

단기는 정해진 순서로 이미지를 분석하고 초안을 검증한다. Agent는 분석·OCR·형식 파서·검증 도구 중 필요한 작업을 선택하고 결과에 따라 다음 작업을 수행한다.

예를 들어 전체 도면 분석에서 치수 충돌이 발견되면 해당 영역을 다시 잘라 분석하고, 치수 연결·합계 검사를 수행한 뒤 해결되지 않은 항목을 사용자에게 제시할 수 있다.

S4는 단일 호출이며, 응답 검증·재요청·치수 대조·확정값 보호는 프로그램이 수행한다([extract.ts](../src/server/floorPlanAi/extract.ts), [proposal.ts](../src/lib/floorPlan/ai/proposal.ts)). 가장 작은 확장 후보는 모델에 "영역을 잘라 확대해 다시 보기" 도구 하나를 주는 방식이다. 이 도구가 조밀한 도면의 정확도를 실제로 높이는지 S5 평가 세트로 비교한 뒤 도입 여부를 정한다.

### 도입 판단과 제한

- 단순 모델 호출보다 수동 수정 시간이나 실패 복구율이 실제로 좋아질 때만 채택한다.
- 실행 가능한 도구와 입력·출력 스키마를 제한하고 임의 코드 실행을 기본 기능으로 넣지 않는다.
- 최대 단계 수·재시도·비용·시간을 제한하고 각 실행 근거를 추적한다.
- 사용자 확정값을 변경할 때 차이를 표시하고 미확정 값의 적용과 구분한다.
- 치수·단위·기하 검증은 프로그램이 수행한다. Agent의 자기 평가만으로 통과시키지 않는다.
- 해결되지 않은 충돌은 사용자 검토로 넘긴다. 장시간 반복해 추정값을 확정값처럼 만드는 행동을 허용하지 않는다.

완료 기준: 고정 평가 세트에서 단순 모델 호출과 Agent 방식을 비교해 정확도·수정 시간·비용·처리 시간을 보고하고, 도입 이점이 없으면 기존 방식을 유지한다.

## 10. 장기 평가와 출시 기준

| 평가 영역 | 기록할 항목 |
| --- | --- |
| 기하 | 실제 좌표 대비 벽·개구부 위치와 크기 오차, 외곽·접합 오류 |
| 인식 | 치수-구간 연결, 벽·문·창의 누락/오검출, 가구 분류 |
| 업무 효율 | 수동 수정 횟수·시간, 완료율, 재분석 필요 횟수 |
| 신뢰성 | 미확정값 표시, 사용자 확정값 보존, 단위 오류 차단 |
| 운영 | 도면당 비용, 처리 시간 분포, 실패·재시도·취소율 |
| 렌더링 | 초기 준비 시간, 프레임 시간, 메모리, 교체·재진입 후 상태 |
| 호환성 | 입력 형식·문서 버전·브라우저·기기별 결과 |

평가 데이터와 튜닝용 데이터를 구분하고, 형식·품질·공간 유형별 결과를 별도로 기록한다. 허용 오차와 배포 기준은 실제 사용 목적을 바탕으로 정한다. 렌더링 성공과 원본의 정확한 재현은 별도 항목으로 평가한다.

## 11. 장기 완료 판단

모든 도면을 무조건 자동 변환하는 상태를 완료 기준으로 두지 않는다. 지원하는 도면 유형·형식·공간에 대해 원본 추출, 검증, 보정, 저장, 3D 재현이 이어지고 그 정확도·한계를 측정할 수 있는 상태를 목표로 한다.

각 단계 착수 전에는 단기 결과, 실제 사용 빈도, 수정 비용, 데이터·운영 요구를 확인해 우선순위를 갱신한다. 외부 라이브러리·서비스·모델의 채택은 해당 시점의 공식 문서와 샘플 검증을 거쳐 결정한다.
