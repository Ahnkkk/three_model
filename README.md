# Interior 3D Viewer (프로토타입)

[DEVELOPMENT_PLAN.md](./docs/DEVELOPMENT_PLAN.md)의 1차 구현 범위를 기준으로 만든 실내 3D 시각화 프로토타입입니다.
[OFFICE_RECONFIGURATION_PLAN.md](./docs/OFFICE_RECONFIGURATION_PLAN.md)에 따라 사무실(H형 데스크 2세트 + 원형테이블 2개)을 `/office`에 추가했습니다.

후속 도면 변환 개발은 [단기 계획](./docs/FLOOR_PLAN_3D_SHORT_TERM_PLAN.md)과 [장기 계획](./docs/FLOOR_PLAN_3D_LONG_TERM_PLAN.md)을 따릅니다. 전체 문서 목록은 [docs](./docs/README.md)에 있습니다. 후속 계획의 기능은 아직 구현되지 않았습니다.

| 경로      | 내용                                                                               |
| --------- | ---------------------------------------------------------------------------------- |
| `/`       | 기존 거실(6 × 5 × 2.8m). 동작·시점·설정 기본값 유지                                |
| `/office` | 사무실(18 × 8m). 같은 데이터로 만든 2D 가구 배치도 + 3D 배치 시안(조감도/실내)    |

- Next.js 16 (App Router) · TypeScript · Tailwind CSS 4 · zustand 5
- React Three Fiber 9 · drei 10 · Three.js r187 (`WebGPURenderer` + TSL)
- 외부 에셋 없이 방·가구·PBR 텍스처를 코드로 생성합니다. 설정 파일에서 GLB 모델로 교체할 수 있습니다.

## 실행

```bash
npm install          # postinstall에서 Draco 디코더를 public/decoders/draco 로 복사
npm run dev          # http://localhost:3310
npm run build        # 운영 빌드(output: "standalone" → .next/standalone, Docker 이미지와 같은 결과물)
npm run typecheck
npm run verify          # 타입 검사 + 브라우저 없는 검증 전부(아래 개별 스크립트)
npm run verify:office   # 사무실 회귀(수량·겹침·파티션·문 열림·동선·보행·점프)
npm run verify:viewer   # 공용 1인칭 조작·거실 회귀(장면 값 유지·소파 보행·커피 테이블 점프)
npm run verify:floor-plan · verify:editor · verify:ai · verify:score   # 도면 문서·편집기·AI 초안·평가 채점
npm run verify:browser  # 브라우저 매트릭스(WebGPU·WebGL 2·모바일). dev 서버 필요
```

도면 인식 평가 도구(`eval:floor-plan`·`eval:manual`·`score:floor-plan`·`eval:samples`)는 [평가 사례 안내](examples/floor-plans/eval/README.md)를 참고하세요.

### Docker(Docker Desktop)

```bash
docker compose up -d --build   # 이미지 빌드 + 컨테이너 실행 → http://localhost:3000 (거실), /office (사무실)
docker compose down            # 중지·삭제
```

- `Dockerfile`은 3단계입니다: 의존성 설치(`npm ci`) → 빌드(`next build`, standalone) → 실행(`node server.js`, node 사용자, 소스·node_modules 없음). 기반 이미지는 `node:24-bookworm-slim`입니다.
- 3D 렌더링은 브라우저에서 하므로 컨테이너는 페이지와 정적 파일만 제공합니다. GPU 설정이 필요 없습니다.
- 포트는 `compose.yaml`의 `"3000:3000"`에서 왼쪽 값을 바꿉니다. Docker Desktop에는 healthcheck 상태(healthy)가 표시됩니다.
- WebGPU는 보안 컨텍스트(HTTPS 또는 localhost)에서만 켜집니다. 다른 PC에서 `http://<IP>:3000`으로 접속하면 WebGL 2 대체 경로로 동작하므로, WebGPU가 필요하면 HTTPS 리버스 프록시를 앞에 둡니다.
- 로컬에서 운영 빌드를 직접 띄울 때는 `next start` 대신 standalone 서버를 씁니다(`public`, `.next/static`을 `.next/standalone`에 복사한 뒤 `node .next/standalone/server.js`).

- WebGL 2 대체 경로 강제: `http://localhost:3310/?backend=webgl`, `http://localhost:3310/office?backend=webgl`
- 버전은 `package.json`에 정확한 버전으로 고정되어 있습니다. `overrides`로 `three` 인스턴스를 하나로 강제합니다(`npm ls three`로 확인).

| 구성               | 구현                                                                                         | 비고                                                                          |
| ------------------ | -------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |

| AO                 | GTAO. `builtinAOContext`로 간접광에만 적용                                                   | 품질 '보통' 이상에서 기본으로 켜짐                                            |
| SSR (실험)         | TSL `SSRNode`. 반사율(금속도·거칠기)로 가중해 더함                                           | 기본값은 꺼짐. 화면 밖 영역은 환경맵 반사가 대신함                            |

### 간이 베이크와 실제 베이크

`lightmapBaker.ts`는 Blender 등으로 실제 베이크한 결과가 준비되기 전에 쓰는 해석적 근사입니다. 광선 추적을 하지 않으므로 가구 뒤편의 정확한 가려짐이나 여러 번 반사된 빛은 계산하지 않습니다.

실제 베이크 결과로 바꾸려면 다음 순서로 진행합니다.

1. 고정 물체에 겹치지 않는 라이트맵용 UV(2번째 채널)와 여백을 준비하고, **간접광만** 베이크합니다.
2. 표면 id별로 텍스처 경로, UV 채널, 강도를 설정에 기록합니다(GLB 출력만으로 라이트맵이 연결되지 않으므로 이 정보를 따로 둡니다).
3. `sceneResources.ts`의 3단계(방 표면 재질)에서 `bakeLightmaps()` 결과 대신 로드한 텍스처를 넣습니다(`colorSpace = NoColorSpace`, `channel = 1`).

### 조명 갱신 제한

- 라이트맵은 **현재 가구 배치와 광원을 전제로** 계산됩니다. 가구를 옮기거나 광원 위치·세기를 바꾸면 결과가 맞지 않으므로 다시 베이크해야 합니다. 간이 베이커는 장면을 불러올 때 다시 계산하므로 `config/interior.ts`를 수정하면 자동 반영됩니다.
- 가구(움직일 수 있는 물체)는 라이트맵 없이 환경광으로 간접광을 받습니다. 프로브 기반 간접광은 후속 단계입니다.
- SSR은 화면에 보이는 정보만 반사하므로 화면 밖에 있는 물체는 반사되지 않습니다.

## 에셋 교체

### 가구를 GLB로 교체

`config/interior.ts`의 가구 항목에 `model`을 추가합니다.

```ts
{ id: "sofa", kind: "sofa", label: "소파", model: { url: "/assets/models/sofa.glb" }, position: [0.4, 0, -1.98], size: [2.2, 0.82, 0.92] }
```

- 모델은 `size`에 맞게 균등 스케일하고 바닥 중심을 원점에 맞춥니다. 원본 크기를 그대로 쓰려면 `fitToSize: false`를 지정합니다.
- 같은 모델을 여러 번 배치해도 캐시된 원본을 옮기지 않고 복제본을 만듭니다. 지오메트리와 재질은 원본과 공유합니다.
- 파일이 없거나 불러오지 못하면 경고를 띄우고 절차적 모델로 대체합니다.
- Draco 압축은 로컬 디코더(`/decoders/draco/`)를, Meshopt는 drei 내장 디코더를 씁니다. KTX2는 아직 연결하지 않았습니다.
- 라이트맵 차폐 계산은 `size`와 `bake` 값을 기준으로 합니다. 모델을 바꾸면 `size`도 실제 크기에 맞춰 주세요.

### 재질 텍스처 교체

`config/materials.ts`의 `texture`는 절차적 텍스처입니다. 실제 PBR 텍스처(Poly Haven, ambientCG 등)를 쓰려면 파일 경로 필드를 추가하고 `sceneResources.ts`의 `createMaterial`에서 불러옵니다. 색상 맵은 sRGB, 거칠기·노멀 맵은 Linear로 지정하고, 반복 크기는 `repeat = 1 / metersPerTile`로 맞춥니다. 가구 지오메트리의 UV가 미터 단위이기 때문입니다.

## 사무실 (`/office`)

첨부 이미지(2D 가구 배치도 + 3D 배치 시안)의 공간 구획·수량·배치를 재현합니다. 기준 데이터는 `config/officePlan.ts` 하나이며, 3D 장면·라이트맵 베이크·2D 평면도가 모두 `officeLayout.ts`의 결과를 사용합니다.

| 영역                   | 구현                                                                                                                          |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 대회의실(5 × 8m)       | 세로 테이블(포트 2개) + 14석(양쪽 6석 + 양 끝 1석), 양쪽 긴 벤치, 남쪽 낮은 수납장, 서쪽 창 4개·기둥, 동쪽 유리 파티션·유리문(안쪽으로 열림) |
| 메인 업무공간(10 × 4m) | H형 데스크 2세트(평행 데스크 2개 + 중앙 수납·책 + 모니터·키보드) + 세트당 업무 의자 4개                                       |
| 소회의실(3.6 × 4m)     | 유리 구획(북·동) + 유리문(안쪽으로 열림), 테이블 + 6석                                                                        |
| 오픈 미팅공간(4 × 4m)  | 흰 원형 테이블 2개(대각 배치), 테이블당 의자 3개                                                                              |
| 휴게라운지(3 × 3.6m)   | 기존 소파·암체어·원형 sideTable 재사용(색상만 장면 소유 복제 재질로 변경)                                                     |
| 탕비 영역(3 × 3.4m)    | 상판·하부장·싱크·수전·커피머신·전자레인지·타일 벽, 서측 유리 + 개구부                                                         |
| 입구                   | 남쪽 외벽 실제 개구부 + 문짝(실내 모드), 옆 벽체                                                                              |

- **표시 모드**: 조감도(기본) — 천장 숨김, 남쪽 벽 0.45m 단면, 주황 단면 캡·바닥 테두리, 위에서 비추는 밝은 조명. 실내 — 천장·천장등·전체 벽, 서쪽 창 햇빛. 모드별로 라이트맵(open/closed)·환경맵·카메라 범위·시점이 따로 있습니다. "3D 배치 시안" 제목 옆 조감도·실내 버튼으로 전환하며, 실내를 고르면 3D 영역이 화면 전체로 확장됩니다(같은 Canvas를 키우므로 리소스를 다시 만들지 않음, Esc 또는 상단 "조감도"로 복귀).
- **2D·3D 비교 화면**: 가구 목록·파티션·외벽 개구부·영역이 같은 데이터에서 나오므로 수량·위치·회전·문 위치가 일치합니다. 공간명·치수·H형 ①·②·입구 표식을 표시합니다. 3D 표식은 HTML 오버레이(조감도에서만, 설정에서 끔)입니다.
- **카메라**: 조감도 전체 시점은 방 bounds와 화면 비율로 거리를 계산하고, 화면 비율이 바뀌면(사용자가 카메라를 움직이지 않은 경우) 다시 맞춥니다. 시점 전환 시 FOV도 함께 보간하며, 같은 투영 카메라를 유지해 AO·SSR의 카메라 참조가 바뀌지 않습니다.
- **미니맵**: 전체 화면 레이아웃(거실, 사무실 실내) 우측 상단에 같은 장면 데이터로 그린 평면도와 현재 위치·시선·시야각을 표시합니다(북쪽이 위). 카메라 위치는 프레임 루프에서 DOM 속성만 갱신해 React를 다시 그리지 않습니다. 표시 모드 설정 `minimap`으로 켜며, 1024px보다 좁은 화면에서는 접힌 상태로 시작합니다. 지도를 클릭하면 그 위치로 미끄러지듯 이동합니다(`viewerStore.requestMoveTo` → CameraControls). 높이는 유지하고, 가구·벽 위를 누르면 가장 가까운 빈자리(`collision.nearestFreeSpot`)로 옮겨 누른 대상을 바라보며, 빈 곳을 누르면 시선 방향을 유지합니다.
- **처음으로**: 렌더링 설정 버튼 옆 버튼. 지금 화면에 처음 들어왔을 때의 시점·장소(표시 모드의 기본 시점)로 돌아갑니다 — 거실·사무실 조감도는 전체, 사무실 실내는 입구.
- **1인칭 시점(FPS 게임식)**: 거실, 사무실 실내는 눈(카메라 위치)이 회전 중심입니다(`lib/three/firstPerson.ts`). 화면을 클릭하면 포인터가 잠기고(커서 숨김, 운영체제 가속을 뺀 실제 마우스 이동량 사용) 마우스를 움직이는 대로 시선이 따라갑니다 — 오른쪽으로 움직이면 오른쪽, 위로 움직이면 위(위치·높이 불변, 위아래는 아래 68°·위 65°까지). Esc는 잠금만 풀고(미니맵·버튼을 쓰려면 먼저 해제, 이때 누르고 있던 이동 키는 놓은 것으로 처리해 계속 걸어가지 않음), 사무실 실내에서 한 번 더 누르면 "조감도로 이동할까요?" 확인·취소 창이 뜹니다(Enter·확인 = 이동, Esc·취소·바깥 클릭 = 취소, 창이 열린 동안 보행 키 무시). 잠금을 못 쓰는 환경(터치, Esc 직후 재잠금 제한 등)에서는 누른 채 끌어 돌립니다. 감도는 「렌더링 설정 → 키보드·마우스 조작 → 마우스 감도」(×0.3~×3)에서 바꿉니다. 화면 중앙에는 표식을 두지 않습니다. 휠(터치는 두 손가락)은 화각을 좁히거나 넓혀 화면 중심 기준으로 확대(최대 ×4)·축소(×0.75)하고, 배율은 하단 안내 옆에 표시됩니다. 시점 버튼·처음으로는 배율도 ×1로 되돌립니다. 사무실 조감도는 기존처럼 OrbitControls(대상 주위 회전, 휠로 다가가기)를 씁니다.
- **키보드 조작**: W 앞으로, S 뒤로, A 왼쪽으로, D 오른쪽으로(지금 보는 방향 기준, 위아래를 봐도 바닥과 평행, 대각선도 같은 속도), 방향키는 제자리에서 보는 방향만 바꿈(← → 좌우, ↑ ↓ 위아래, Q·E도 좌우), Shift 빠르게, Space 점프(중력 포물선, `keyboard.jumpHeight` 사무실 1.0m·거실 0.9m). 카메라 설정의 `keyboard`(이동 m/s·회전 도/s)로 켜며, 사무실 조감도에는 두지 않았습니다(페이지 스크롤과 충돌 방지). 입력란에 포커스가 있으면 무시합니다. 이동은 가구 footprint(H형은 데스크 2개 + 중앙 수납부만, 원형 테이블은 원)와 파티션 벽 구간에 충돌하며 벽을 따라 미끄러집니다(`lib/three/collision.ts`, 몸통 반지름 `keyboard.bodyRadius` 0.2m). 러그·액자는 무시하고, 펜던트처럼 눈높이보다 위에 있는 것은 통과합니다. 열린 문짝(파티션 문·출입문)도 막습니다 — 대회의실·소회의실 문을 회의실 안쪽으로 열리게 바꿔 H형 ① 옆 통로를 비웠습니다.
- **점프로 올라서기·넘어가기**: 몸에 발 높이(바닥 = 0)가 있어, 사물은 윗면이 발 + 턱(0.1m)보다 높을 때만 앞을 막습니다(`collision.stepWalker`). 점프해서 발이 사물 윗면 근처까지 올라가면 그 위로 지나가거나 윗면에 착지해 서 있을 수 있고(책상·회의 테이블 0.74m, 벤치 0.78m, 커피 테이블 0.4m, 소파 0.82m 등), 발(몸 중심, 판정 반지름 `FOOT_RADIUS` 0.08m)이 가장자리를 벗어나는 즉시 중력으로 떨어집니다. 눈높이(발 → 카메라)는 시점에 도착할 때 정해지고 걷기·점프·마우스 조작으로 바뀌지 않으므로, 내려오면 올라가기 전 카메라 높이로 정확히 돌아옵니다. 달리면서(Shift) 점프하면 라운지 테이블 같은 낮은 사물을 한 번에 뛰어넘습니다. 파티션·책장처럼 높은 것은 넘지 못하고, 머리는 카메라 위치 범위(천장 아래)를 넘지 않습니다. 시점 버튼·처음으로·미니맵 이동은 바닥 기준 위치로 이동합니다.
- **성능**: 의자 34개는 종류·색상별 부품 인스턴싱(부품 수만큼의 드로콜), 파티션 프레임·유리는 선분마다 병합, 라이트맵은 사무실 전용 낮은 텍셀 밀도(10/m).
- **장면 분리**: 진입 시 `resetForScene()`으로 시점·밝기·표시 모드·경고·통계·효과를 초기화하고, 리소스는 장면마다 따로 만들고 해제합니다. 거실 ↔ 사무실 왕복 후 거실 값이 기본값과 같은 것을 확인했습니다.

### 가정·미확정 항목

이미지로 확정할 수 없는 값은 `OFFICE_ASSUMPTIONS`(2D 가구 배치도 패널의 "가정·미확정 항목")와 `officePlan.ts`에 모아 두었습니다.

1. 외곽 18 × 8m(벽 두께 0.2m는 바깥쪽).
2. 오른쪽 3.6 + 3.4m와 8.0m의 차이 1.0m → 라운지와 탕비 사이 조정 구간. 이미지의 나무문은 열린 상태로 두어 막지 않습니다.
3. 소회의실 깊이 4m, 입구 연결 공간 2.4m.
4. H형 세트당 4석(총 8석), 원형 테이블당 3석 → 의자 합계 34개.
5. 서쪽 창 4개(폭 1.3m), 출입문 폭 1.0m, 실내문 폭 0.82~0.9m, 벽 높이 2.8m.
6. 라운지는 조정 구간 쪽 개구부, 탕비는 입구 쪽 서측 개구부로 출입.

### 배치 검증(`npm run verify:office`, `npm run verify:viewer`)

`verify:office`(사무실 회귀)는 다음을 검사합니다.
- 배치: 좌표 변환 왕복, 회전 footprint, 필수 수량(대회의 14·소회의 6·H형 2·원형 2), 방 경계, 가구 겹침(의자-테이블 제외), 파티션 관통, 문 열림 영역 간섭, 입구에서 모든 공간까지의 동선(0.1m 격자, 통과 반경 0.25m). 일부러 망가뜨린 배치로 검증기 자체가 오류를 잡는지도 확인합니다.
- 키보드 보행 충돌: 회의실 문짝이 안쪽으로 열림, 문짝-가구 겹침 없음, 유리 파티션 차단, 대회의실 문 통과, H형 수납부 앞 정지, 무작위 4000걸음 침투 없음, 실내 시점 시작 위치, 가구까지 고려한 입구→모든 공간 동선(반지름 0.2m)
- 미니맵 클릭 이동의 도착점: 빈 곳은 그대로, 테이블 위는 가까운 빈자리, 방 밖은 범위 안
- 점프 시뮬레이션: 점프 없이는 책상에 막힘, 책상 위로 올라섬, 책상 위를 지나 건너편 바닥으로, 천장 아래에서 멈춤, 라운지 테이블 뛰어넘기, 유리 파티션은 못 넘음, 가장자리에서 바로 떨어짐, 내려오면 원래 카메라 높이

같은 검증 결과가 사무실 화면의 2D 가구 배치도 패널에도 표시됩니다.

`verify:viewer`는 장면과 무관한 1인칭 조작과 거실 회귀를 검사합니다.
- 1인칭 조작: W 앞·S 뒤·A 왼쪽·D 오른쪽이 보는 방향 기준으로 움직임, 방향키는 위치 그대로 시점만 회전, 대각선 같은 속도, 마우스 이동·드래그 방향과 감도·위아래 한계, 휠 확대·축소 방향과 범위
- 거실 회귀: 설정 보존, 소파 시점 보행, 커피 테이블 점프

- 아직 하지 않은 항목: 실제 기준 기기 측정, 모바일 기기 실측·터치 조작 검증, 장면 반복 진입 시 GPU 메모리 추적, 사무실 가구의 GLB 교체 실패 경로(공용 경로는 거실에서 검증)

## 알려진 제한 / 후속 작업

- 지역 반사 프로브(박스 투영)와 방 사이 반사 전환: 미구현. 현재는 방 전체에 환경맵 하나를 씁니다.
- 조명 프로브, SSGI, 시간적 안티앨리어싱(TRAA): 미구현.
- SSR은 실험 기능입니다. 환경 반사 위에 더해지므로 약간 중복되고, 매끄러운 바닥에서만 효과가 보입니다.
- 콘솔의 `THREE.Clock deprecated` 경고는 R3F 내부에서 발생하며 동작에는 영향이 없습니다.
- 사무실 간이 베이크는 외곽 6면만 계산합니다. 내부 파티션은 접촉 차폐만 근사하고, 방 사이의 빛 전달·가려짐은 계산하지 않습니다. 파티션·가구는 라이트맵 없이 직접광·환경광·AO로 표현합니다.
- 사무실 환경맵은 하나(모드별)이며 방별 지역 반사는 없습니다.
- 조감도에서 숨긴 천장·낮춘 남쪽 벽은 그림자도 만들지 않습니다(열린 모형 전제의 별도 조명·베이크 사용).
- 의자·모니터 등은 멀리서 보는 수준의 단순 형상입니다(캐스터·케이블 등 생략).
